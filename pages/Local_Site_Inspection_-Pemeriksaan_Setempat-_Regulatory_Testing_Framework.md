# Local Site Inspection (Pemeriksaan Setempat): Regulatory Testing Framework

**Page summary:** The *regulatory sandbox* concept for the Draft Regulation on Local Site Inspection (*Pemeriksaan Setempat*, "PS") should **not** be written into the body of the PERMA (Supreme Court Regulation) as a formal "sandbox." Instead, it should be used as a **method for designing and testing norms** before the final norm is enacted. This page sets out that framework in full.

\_\_TOC\_\_

## Background

This approach fits well with the process currently being developed by **Pustrajak** (the Supreme Court's Research and Development Center), namely:

- strengthening the legal basis,
- standardizing procedures, and
- synchronizing with the draft PERMA.

## Regulatory Cycle Model

The PS draft is shifted from a linear model into a **regulatory cycle** that treats the draft as a *regulatory prototype* before it becomes final regulation.

**Old model (linear):**

    Problem → Draft PERMA → Enacted → Implemented

**New model (cycle, stronger):**

    Practical Problem → Evidence → Draft Norm → Regulatory Testing
    → Implementation Test → Evaluation → Norm Refinement → PERMA
    → Implementation → Monitoring → Regulatory Learning

## Local Site Inspection Regulatory Testing Framework

Suggested name for the concept: **"Local Site Inspection Regulatory Testing Framework"** — not "Judicial Regulatory Sandbox" within the body of the PERMA.

### Testing Objectives

The framework tests whether a draft norm truly:

- can be implemented by the courts;
- provides procedural certainty;
- does not add unnecessary burden;
- guarantees the rights of the parties;
- produces verifiable documentation;
- reduces variation in practice;
- can be applied across all four judicial environments; and
- does not create new problems.

## The PS Draft as a Regulatory Prototype

Each norm in the draft PERMA is not tested by asking *"Is this sentence well-written?"* but rather:

### Example: The Norm on Ordering a Site Inspection

**Draft norm:**

**Regulatory testing applied to this norm:**

| Question                        | Test                               |
|---------------------------------|------------------------------------|
| Who may propose it?             | Judge / the parties                |
| When is it ordered?             | At a specific stage of examination |
| What are the criteria?          | Necessity test                     |
| Is it mandatory?                | Not automatic                      |
| What must be stated?            | Object, reasons, location          |
| Who must attend?                | Panel / court clerk / the parties  |
| How is notice given?            | A defined standard                 |
| What if the object is far away? | Delegation mechanism               |
| What if the object has changed? | Documentation                      |
| How are results recorded?       | Official report (*berita acara*)   |
| How is visual evidence treated? | Evidence protocol                  |
| How is security handled?        | Risk protocol                      |
| How are costs handled?          | Cost protocol                      |

In this way, **every norm has its own "test case."**

## Six Layers of the PS Draft

### Layer 1 — Legal Validity

Does the norm have a legal basis? References: HIR/RBg/Rv (Indonesian civil procedure codes), SEMA (Supreme Court Circulars), related PERMAs, other regulations, and relevant court decisions.

### Layer 2 — Operational Validity

Can the norm actually be carried out? Tested through the workflow:

    Order → Notice → Preparation → Departure
    → Inspection → Measurement → Documentation → Official Report
    → Return to Trial

### Layer 3 — Evidence Validity

**Very important.** A site inspection must not produce only:

It must produce **structured evidence**:

    Object → Location → Boundary → Size → Condition → Identity
    → Parties' Statements → Measurement → Photo/Video
    → Findings → Discrepancy

So that the site inspection becomes an **Evidence Acquisition & Verification Process**, not merely a field visit.

### Layer 4 — Rights & Procedural Fairness

Every draft norm is tested against whether:

- the Plaintiff and Defendant receive equal opportunity;
- each party may point out the object according to their own account;
- objections can be recorded;
- statements made by the parties are distinguished from the judge's own findings;
- documentation can be traced;
- there is no substantive communication outside the formal procedure.

### Layer 5 — Risk & Security

Proposed as a **dedicated chapter**. PS Risk Register:

| Risk           | Example                                                  |
|----------------|----------------------------------------------------------|
| Physical       | Conflict at the site                                     |
| Security       | Crowds / outside parties                                 |
| Evidence       | The object has changed                                   |
| Measurement    | Differing measurement results                            |
| Procedural     | A party fails to appear                                  |
| Administrative | Improper notice                                          |
| Financial      | Inconsistent costs                                       |
| Data           | Uncontrolled documentation                               |
| Integrity      | Interference by a party                                  |
| Execution      | Object unclear, making the judgment difficult to enforce |

## PS Test Cases

Before the PERMA is finalized, the draft is tested against several synthetic/realistic case scenarios.

| Test Case                  | Object Scenario                                        | Testing Objective                                                                                                  |
|----------------------------|--------------------------------------------------------|--------------------------------------------------------------------------------------------------------------------|
| **A — Simple land parcel** | One parcel of land, clear boundaries, parties present  | Test the basic procedure                                                                                           |
| **B — Unclear boundaries** | Land with unclear boundaries                           | Test measurement, conflicting claims, and documentation                                                            |
| **C — Changed object**     | A building has changed since the claim was filed       | Test temporal evidence                                                                                             |
| **D — Distant object**     | The object is far from the court                       | Test delegation and coordination                                                                                   |
| **E — Disputed accounts**  | The parties disagree about the object                  | Test how differing versions are recorded without the judge becoming a party that unilaterally determines the facts |
| **F — Security risk**      | The object poses a security risk                       | Test the security protocol                                                                                         |
| **G — Digital evidence**   | A site inspection in a case involving digital evidence | Test integration of photos/videos/electronic documents                                                             |

## Norm → Test → Evidence

Described as the **key methodological innovation** in the PS draft. Every norm has three components:

    NORM     → What is required or permitted?
       ↓
    TEST     → How do we know the norm can be carried out?
       ↓
    EVIDENCE → What proves the norm was successfully applied?

### Applied Examples

| Norm                                                                  | Test                                                            | Evidence                                                                 |
|-----------------------------------------------------------------------|-----------------------------------------------------------------|--------------------------------------------------------------------------|
| Notice of the site inspection is given to the parties.                | Was the notice received before the inspection took place?       | Bailiff's return (*relaas*)/electronic notification + timestamp.         |
| The results of the site inspection are set out in an official report. | Can the official report reconstruct what was actually examined? | Official report + list of objects + measurement results + documentation. |
| The parties may point out the object according to their own account.  | Can differing accounts be recorded?                             | Statement/objection log.                                                 |

## The Regulatory Sandbox Is Not a PERMA Norm

**Important:** The regulatory sandbox is kept separate, across three distinct layers:

| Layer                     | Function                                                                              |
|---------------------------|---------------------------------------------------------------------------------------|
| **A. PERMA**              | The binding legal norm                                                                |
| **B. Guidelines / SOP**   | How the norm is carried out                                                           |
| **C. Regulatory Testing** | How the draft norm is tested before enactment, and how its effectiveness is evaluated |

## Implications for the PS Policy Brief

Local Site Inspection becomes a **pilot case for Evidence-Based Regulatory Design**.

**Not simply:**

**But rather, the policy thesis:**

This aligns with the position of the site inspection in Pustrajak's study as an instrument for ensuring the consistency of documents, the parties' claims, and the factual condition of the object of the case — while also addressing the need for standardization across judicial environments.

Accordingly, the draft PERMA on Local Site Inspection is no longer merely a "draft regulation," but becomes a **regulatory prototype** that can be tested, evidenced, evaluated, and then refined before being enacted.
